        Introduction

        This document provides comprehensive technical specifications for the DentalNote.AI Admin Dashboard. It is intended for the development team to ensure a clear understanding of the project's architecture, components, and the required backend API.

        The Admin Dashboard is a single-page application (SPA) designed for administrators to manage the core data of the DentalNote.AI platform. Key functionalities include:

        • Analytics: Viewing key metrics like user growth and API usage.
        • User Management: Managing both regular subscribers and admin users.
        • Template Management: A comprehensive system for creating and organizing Note Templates, Care-Call Instructions, and Post-Op Instructions.

        Tech Stack

        The frontend is built with standard web technologies, focusing on simplicity and performance. The backend requirements are defined in this document and can be implemented with any preferred stack (e.g., Node.js/Express, Python/Django, etc.).

        Sidebar Navigation

        The primary navigation is a fixed sidebar. It allows users to switch between the different management pages of the dashboard.

        JavaScript Logic:

        Page switching is handled by adding/removing an `.active` class on both the sidebar links and the corresponding page content divs. The `data-page` attribute on the link must match the `id` of the content div.

        
const sidebarLinks = document.querySelectorAll('.sidebar-link');
const pages = document.querySelectorAll('.page-content');

sidebarLinks.forEach(link => {
    link.addEventListener('click', (e) => {
        e.preventDefault();
        const pageId = link.dataset.page;

        // Update active link
        sidebarLinks.forEach(l => l.classList.remove('active'));
        link.classList.add('active');

        // Show active page content
        pages.forEach(p => p.classList.remove('active'));
        document.getElementById(pageId).classList.add('active');
    });
});

        Template Management

        This is the most complex component, featuring a tabbed interface to manage three types of templates. Each tab has a searchable, sortable list and a button to launch an "Add" modal.

        Tab Switching Logic:

        Similar to the main page navigation, tab switching is handled by toggling an `.active` class on the tab buttons and their corresponding content panels.

        
const templateTabButtons = document.querySelectorAll('.template-tab-button');
const templateTabContents = document.querySelectorAll('.template-tab-content');

templateTabButtons.forEach(button => {
    button.addEventListener('click', () => {
        // Update active tab button
        templateTabButtons.forEach(btn => btn.classList.remove('active'));
        button.classList.add('active');

        // Show active tab content
        templateTabContents.forEach(content => content.classList.remove('active'));
        document.getElementById(button.dataset.tab).classList.add('active');
    });
});

        Dynamic Modals

        Modals are used for creating and editing items. The content for each modal is injected dynamically via JavaScript upon the first click. This keeps the initial DOM clean and improves performance.

        Modal Invocation Pattern:

        The example below shows the pattern for the "Add Post-Op Instruction" modal. This pattern is repeated for all modals in the application.

        
const addPostOpModal = document.getElementById('add-post-op-modal');
const addPostOpBtn = document.getElementById('add-post-op-btn');

const openAddPostOpModal = () => {
    const modalContent = addPostOpModal.querySelector('.modal-content');
    // Inject HTML only if it's the first time opening the modal
    if (!modalContent.innerHTML) {
        modalContent.innerHTML = \`
            <form id="add-post-op-form">
                <h3 class="text-2xl font-bold mb-6 border-b pb-4">Add New Post-Op Instruction</h3>
                <!-- ... form fields ... -->
                <div class="flex justify-end space-x-4 mt-8 pt-6 border-t">
                    <button type="button" id="add-post-op-cancel-btn">Cancel</button>
                    <button type="submit">Save Instructions</button>
                </div>
            </form>
        \`;

        // Attach event listeners after injecting content
        document.getElementById('add-post-op-cancel-btn').addEventListener('click', closeAddPostOpModal);
        document.getElementById('add-post-op-form').addEventListener('submit', (e) => {
            e.preventDefault();
            // Handle form submission logic
            const newPostOpName = document.getElementById('post-op-title').value;
            if (newPostOpName) {
                // In a real app, this would be an API call
                const newPostOp = { id: Date.now(), name: newPostOpName, added: '2025-07-16', edited: '2025-07-16' };
                templateData.postOp.push(newPostOp);
                renderList('post-op-list', templateData.postOp);
                closeAddPostOpModal();
            }
        });
    }
    addPostOpModal.classList.add('active');
};

const closeAddPostOpModal = () => addPostOpModal.classList.remove('active');

addPostOpBtn?.addEventListener('click', openAddPostOpModal);
addPostOpModal?.addEventListener('click', e => { 
    if (e.target === addPostOpModal) closeAddPostOpModal(); 
});

        API Endpoints

        The following endpoints are required to support the frontend functionality. All `POST` and `PUT` requests should include the corresponding data model in the request body.

        /api/templates/notes

        Endpoints for managing Note Templates.

        GET - Fetches all note templates.

        POST - Creates a new note template.

        PUT /:id - Updates an existing note template.

        DELETE /:id - Deletes a note template.

        /api/templates/care-calls

        Endpoints for managing Care-Call Instructions.

        GET - Fetches all care-call instructions.

        POST - Creates a new care-call instruction.

        PUT /:id - Updates an existing care-call instruction.

        DELETE /:id - Deletes a care-call instruction.

        /api/templates/post-op

        Endpoints for managing Post-Op Instructions.

        GET - Fetches all post-op instructions.

        POST - Creates a new post-op instruction.

        PUT /:id - Updates an existing post-op instruction.

        DELETE /:id - Deletes a post-op instruction.
